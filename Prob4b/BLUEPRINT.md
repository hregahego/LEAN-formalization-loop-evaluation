# Blueprint: a finite-conductor ring that is not quasi-coherent (Problem 4(b))

A roadmap for formalizing, in **Lean 4 + Mathlib**, the result in `SKETCH.md`.
We build a 14-dimensional graded local `F₂`-algebra `B = F₂[a,b,c,d]/((a,b,c,d)³, ad+bc)`,
a `B`-module `M = B⁴/Bv` with `v = (a,b,c,d)`, the idealization `C = B ⋉ M`, and finally
the "eventually diagonal" ring `R = Δ(B) + C^(ℕ) ⊆ C^ℕ`. The single idea that makes it
work is a **colon calculation in `B`**: `(I : m) = I + m²` for every ideal `I` generated by
at most two elements. That one identity forces `M` (and hence `C`, hence `R`) to preserve
*annihilators* and *pairwise* principal intersections, while an explicit element
`u = [(0, ab+b², 0, bc+bd)] ∈ M` witnesses that a *triple* intersection is not preserved.
Spreading that defect over infinitely many coordinates of `C^ℕ` makes the triple
intersection non-finitely-generated.

- **Headline target (frozen theorem `exists_finiteConductor_not_quasiCoherent`).**
  `∃ (S : Type) (inst : CommRing S), FiniteConductor S ∧ ¬ QuasiCoherent S`.
  Both predicates are frozen in `Defs.lean` as the genuine textbook notions:
  `FiniteConductor S` = "`(0 : x)` is f.g. for every `x`, and `Sx ⊓ Sy` is f.g. for all
  `x, y`"; `QuasiCoherent S` = "`(0 : x)` is f.g. for every `x`, and `⨅ i, S·(f i)` is
  f.g. for **every** `n : ℕ` and **every** family `f : Fin n → S`". The witness is exhibited
  by the companion frozen theorems `R_finiteConductor` and `R_not_quasiCoherent`, and the
  half-statement `R_triple_inter_not_fg` is frozen on its own because it is the actual
  content of Step 5. The sanity lemma `quasiCoherent_imp_finiteConductor` is also frozen:
  it certifies that the two predicates are ordered the way the problem assumes, so the
  headline is a genuine strict separation and not a comparison of incomparable notions.
- **Recommended intermediate milestone (prove first):**
  `B_colon_two_gen` — `∀ x y : Balg, (span {x, y} : Ideal Balg).colon mB = span {x, y} ⊔ mB ^ 2`.
  This is the mathematical heart. Once it is available, *every* module- and ring-level
  identity of Steps 2 and 4 is a short, purely elementary manipulation of the presentation
  `0 → Bv → B⁴ → M → 0` (see Stage C: **no `Tor` is needed**), and the rest of the project
  is bookkeeping. It is also citable on its own as a structural fact about `B`.
- **Setting / ground assumptions:** everything is commutative algebra over the field
  `F₂ = ZMod 2`. `B` is a *finite* (14-dimensional, `2¹⁴`-element) graded local ring with
  `m³ = 0`; `M` is a finitely generated `B`-module; `C = B ⋉ M` is again finite; only `R`
  is infinite, and it is infinite only in the trivial "sequences" direction. There is **no
  analysis, no topology, no inequalities, no cardinal arithmetic** — the only genuinely
  infinite object is `ℕ` used as an index set, and the only thing we ever do with it is
  "finite support / cofinitely constant". Characteristic 2 is used freely (`−1 = 1`), so
  `ad + bc = 0` and `ad = bc` are the same statement.

> **Why this is tractable.** Every hard step is a *finite* linear-algebra statement over
> `F₂`: `B` has an explicit 14-element monomial basis, `M` is a quotient of `B⁴`, and the
> colon lemma reduces (Stage B) to a question about the 4-dimensional space `V = ⟨a,b,c,d⟩`
> and the 9-dimensional space `W = Sym²V/⟨ad+bc⟩` — objects small enough to argue about by
> explicit coordinates. The real risk is **not** depth, it is (i) **mis-modeling**: writing
> `QuasiCoherent` with the intersection bounded to `n ≤ 2`, or `FiniteConductor` with an
> extra hypothesis, would make the headline vacuous or false; (ii) **collapse**: if the
> relation ideal is written wrongly (e.g. `m²` instead of `m³`, or forgetting `ad + bc`),
> `B` degenerates and `u` becomes `0`, at which point everything below is provable and
> meaningless — this is why `B_nontrivial`, `B_relation` and `M_u_ne_zero` are frozen
> *guardrails*; and (iii) **over-reach**: assuming the colon lemma, or assuming
> `xM ∩ yM = (xB ∩ yB)M`, instead of proving it.

### 2. Freeze the Definitions (`Defs.lean`)

Define every object the proof needs, **in dependency order**. **Make decisive modeling
choices here and write them down — they cannot change later.**

**D0 — generic colon / annihilator vocabulary.**

```lean
/-- The colon ideal `(I : J) = {r | r * J ⊆ I}`. -/
def colonI {S : Type*} [CommRing S] (I J : Ideal S) : Ideal S := I.colon J

/-- `(0 : x)`, the annihilator ideal of a ring element. -/
def ann {S : Type*} [CommRing S] (x : S) : Ideal S := colonI ⊥ (Ideal.span {x})

/-- `(0 :_N x)`, the annihilator submodule of `x` acting on a module `N`. -/
def annM {S : Type*} [CommRing S] (N : Type*) [AddCommGroup N] [Module S N] (x : S) :
    Submodule S N := LinearMap.ker (LinearMap.lsmul S N x)

/-- `I • N` for `N` the whole module — i.e. the submodule `I·N`. -/
def smulTop {S : Type*} [CommRing S] {N : Type*} [AddCommGroup N] [Module S N]
    (I : Ideal S) : Submodule S N := I • (⊤ : Submodule S N)
```

> **MODELING DECISION (D0).** `(0 : a)` is rendered as the Mathlib colon ideal
> `(⊥ : Ideal S).colon (Ideal.span {a})`, **not** as a hand-rolled `Submodule` with carrier
> `{y | y * a = 0}`. Reason: `Submodule.colon` is the textbook object, comes with
> `Submodule.mem_colon`, and makes `(I : m)` and `(0 : a)` literally the same construction,
> which is what the sketch's Step 2 argument needs. Rejected alternative:
> `Submodule.annihilator (Ideal.span {a})` — equivalent, but then the colon lemma of Stage B
> would need a second, different vocabulary. Stage A must produce and log the bridge lemma
> `mem_ann : y ∈ ann x ↔ y * x = 0`. `xM` is always written `smulTop (Ideal.span {x})`
> (never as `LinearMap.range (lsmul x)`) so that `xM` and `(xB ⊓ yB)M` are the *same shape*
> of term; Stage C must record `smulTop_span_singleton : m ∈ smulTop (Ideal.span {x}) ↔ ∃ n, x • n = m`.

**D1 — the two predicates under comparison.**

```lean
/-- `S` is a finite-conductor ring. -/
def FiniteConductor (S : Type*) [CommRing S] : Prop :=
  (∀ x : S, (ann x).FG) ∧ (∀ x y : S, (Ideal.span {x} ⊓ Ideal.span {y} : Ideal S).FG)

/-- `S` is quasi-coherent. -/
def QuasiCoherent (S : Type*) [CommRing S] : Prop :=
  (∀ x : S, (ann x).FG) ∧
  (∀ (n : ℕ) (f : Fin n → S), (⨅ i, Ideal.span {f i} : Ideal S).FG)
```

> **MODELING DECISION (D1).** These are the definitions the whole problem is *about*, so
> they are rendered with no slack whatsoever. `FiniteConductor` quantifies over **all**
> `x y : S` (not over a generating set, not over nonzerodivisors). `QuasiCoherent`
> quantifies over **all `n : ℕ` and all families `f : Fin n → S`** — an arbitrary finite
> intersection of principal ideals, exactly as `SKETCH.md` states it. Rejected alternatives:
> (a) bounding `n ≤ 3` — that would still make our counterexample true, but it would no
> longer be the textbook notion, so the headline would be a different theorem; (b) using a
> `Finset S` with `⨅ x ∈ s, span {x}` — equivalent, but `Fin n → S` matches "`Ra₁ ∩ ⋯ ∩ Ra_n`"
> literally and is easier to instantiate at the explicit triple in Stage F. Note the `n = 0`
> case gives `⊤`, which is f.g.; this is harmless and does **not** weaken the predicate.
> **Consequence a later stage must respect:** `QuasiCoherent S → FiniteConductor S` is
> obtained by instantiating `n := 2`, so Stage F must actually perform that instantiation
> (frozen theorem `quasiCoherent_imp_finiteConductor`) rather than assume it.

**D2 — the polynomial ring and the relation ideal.**

```lean
abbrev Pol : Type := MvPolynomial (Fin 4) (ZMod 2)

/-- the irrelevant maximal ideal `(a,b,c,d)` upstairs -/
def mPol : Ideal Pol :=
  Ideal.span {MvPolynomial.X 0, MvPolynomial.X 1, MvPolynomial.X 2, MvPolynomial.X 3}

/-- `(a,b,c,d)³ + (ad + bc)` -/
def relIdeal : Ideal Pol :=
  mPol ^ 3 ⊔ Ideal.span {MvPolynomial.X 0 * MvPolynomial.X 3 + MvPolynomial.X 1 * MvPolynomial.X 2}

/-- `B = F₂[a,b,c,d] / ((a,b,c,d)³, ad + bc)` -/
abbrev Balg : Type := Pol ⧸ relIdeal

def xa : Balg := Ideal.Quotient.mk relIdeal (MvPolynomial.X 0)
def xb : Balg := Ideal.Quotient.mk relIdeal (MvPolynomial.X 1)
def xc : Balg := Ideal.Quotient.mk relIdeal (MvPolynomial.X 2)
def xd : Balg := Ideal.Quotient.mk relIdeal (MvPolynomial.X 3)

/-- the maximal ideal `m = (a,b,c,d)` of `B` -/
def mB : Ideal Balg := Ideal.span {xa, xb, xc, xd}
```

> **MODELING DECISION (D2).** `B` is the **honest quotient of a multivariate polynomial
> ring**, not a hand-built 14-dimensional structure with tabulated structure constants.
> Trade-off, decided deliberately: the quotient model gives `CommRing`, commutativity,
> associativity and distributivity **for free** from Mathlib and gives
> `IsNoetherianRing Balg` from the Hilbert basis theorem plus `Ideal.Quotient` — none of
> which we then have to `decide`. The price is that `Balg` is `noncomputable`-flavoured:
> **`decide` will not reduce on `Balg`**, so every nonvanishing claim (`u ≠ 0`,
> `aB ⊓ bB ⊓ (a+b)B = ⊥`) must be certified by an explicitly constructed **`ZMod 2`-linear
> normal-form map**, built in Stage A, not by kernel computation. Rejected alternative:
> `Balg := Fin 14 → ZMod 2` with tabulated multiplication — `decide`-friendly, but then
> associativity is 14³ = 2744 basis triples to discharge and `IsNoetherianRing` has to be
> re-derived; worse, a typo in one structure constant silently changes the ring and no
> guardrail would catch it. The relation ideal is written `mPol ^ 3 ⊔ span {ad + bc}`
> — note **`^ 3`, not `^ 2`**, and the relation is `X 0 * X 3 + X 1 * X 2` (`ad + bc`),
> **not** `X 0 * X 1 + X 2 * X 3`. Getting either wrong collapses the construction.
> Naming: `xa xb xc xd` rather than `a b c d` so that ordinary Mathlib variable names in
> support files never shadow the frozen generators.

**D3 — the module `M` and the defect element `u`.**

```lean
/-- `v = (a, b, c, d) ∈ B⁴` -/
def vvec : Fin 4 → Balg := ![xa, xb, xc, xd]

/-- `Bv ⊆ B⁴` -/
def Nsub : Submodule Balg (Fin 4 → Balg) := Submodule.span Balg {vvec}

/-- `M = B⁴ / Bv` -/
abbrev Mmod : Type := (Fin 4 → Balg) ⧸ Nsub

/-- the defect element `u = [(0, ab + b², 0, bc + bd)]` -/
def uElt : Mmod :=
  Submodule.Quotient.mk ![0, xa * xb + xb * xb, 0, xb * xc + xb * xd]
```

> **MODELING DECISION (D3).** `M` is the **quotient module** `B⁴ ⧸ span {v}`, matching
> `SKETCH.md` Step 2 literally; `Fin 4 → Balg` is used for `B⁴` (rather than
> `Balg × Balg × Balg × Balg`) so that `![…]` literals and coordinatewise reasoning are
> available, and so `v` is a single named vector. `Bv` is `Submodule.span Balg {vvec}`, i.e.
> the *cyclic* submodule generated by `v` — **not** `LinearMap.range` of anything, and
> **not** `Ideal.span`, since it is a submodule of `B⁴` and not an ideal (see the
> "keep module-side and ring-side objects distinct" rule below). `u` is frozen as the exact
> vector of the sketch. **Consequence later stages must respect:** three explicit witnesses
> for `u`, all verified by hand and all valid in `B⁴` (using `ad = bc`, char 2):
> `u = xa • ![xb, xb, xd, xd] + xb • vvec`, `u = xb • ![0, xa+xb, 0, xc+xd]` (exact, no `v`
> correction), and `u = (xa+xb) • ![0, xb, 0, xd]` (exact, uses `ad = bc`). These are the
> witnesses Stage C must use; do not go looking for others.

**D4 — the idealization `C = B ⋉ M`.**

```lean
/-- `C = B ⋉ M`, the trivial square-zero (Nagata) extension. -/
abbrev Cring : Type := TrivSqZeroExt Balg Mmod

/-- `B ↪ C`, `x ↦ (x, 0)` -/
def iota : Balg →+* Cring := TrivSqZeroExt.inlHom Balg Mmod |>.toRingHom
```

> **MODELING DECISION (D4).** Use Mathlib's `TrivSqZeroExt R M` rather than hand-rolling
> `B × M` with `(x,m)(y,n) = (xy, xn + ym)`. Mathlib already supplies `CommRing`
> (`TrivSqZeroExt.instCommRing`, needs `CommRing Balg` + `Module Balg Mmod`), the ring hom
> `inl`, the projection `fst`, and the `ext`/`fst`/`snd` simp set. Hand-rolling would mean
> discharging ring axioms by hand — forbidden by the "discharge ring axioms once" rule.
> If the exact spelling of the ring-hom bundling differs in the pinned Mathlib
> (`TrivSqZeroExt.inlHom` is an `AlgHom` there), SETUP must adjust the `def` **before**
> freezing so that `iota` is a `Balg →+* Cring`; after freezing it cannot change.
> **Consequence:** the two facts every later stage uses are
> `x ∈ Cring` decomposition `c = TrivSqZeroExt.inl c.fst + TrivSqZeroExt.inr c.snd`, and
> the "extension of an ideal" description `Ideal.map iota J = {c | c.fst ∈ J ∧ c.snd ∈ smulTop J}` —
> Stage D must prove this description as a support lemma (`map_iota_eq`) before anything else.

**D5 — the amplified ring `R = Δ(B) + C^(ℕ)`.**

```lean
/-- `R = Δ(B) + C^(ℕ)`: the sequences in `C^ℕ` that are constant, equal to a
    diagonal element of `B`, outside a finite set of coordinates. -/
def Rsub : Subring (ℕ → Cring) where
  carrier := {f | ∃ x : Balg, {n | f n ≠ iota x}.Finite}
  -- zero_mem', one_mem', add_mem', neg_mem', mul_mem' : all by taking `x := 0`, `1`,
  -- `x + y`, `-x`, `x * y` and `Set.Finite.union`.

abbrev Ramp : Type := Rsub

/-- `Δ : B → R`, the diagonal copy of `B`. -/
def diag : Balg →+* Ramp := ...   -- x ↦ ⟨fun _ => iota x, ⟨x, by simp⟩⟩

/-- the element of `R` carrying the defect `(0, u) ∈ C` in coordinate `n` and `0` elsewhere. -/
def uAt (n : ℕ) : Ramp :=
  ⟨fun k => if k = n then TrivSqZeroExt.inr uElt else 0, ⟨0, (Set.finite_singleton n).subset (by ...)⟩⟩
```

> **MODELING DECISION (D5).** `R` is defined **intrinsically** as the sub*ring* of `C^ℕ`
> of sequences that are *cofinitely equal to a constant diagonal element of `B`*, rather
> than as an abstract sum `Δ(B) + C^(ℕ)` of two submodules. Reason: `f ∈ Rsub ↔ ∃ x,
> {n | f n ≠ iota x}.Finite` is directly usable — every Stage E/F argument is "take the tail
> value `x`, take the finite exceptional set `S`" — whereas the sum-of-submodules form would
> require destructing a sum every time. The two are the same set: `f = Δ(x) + g` with `g`
> finitely supported iff `f n = iota x` off a finite set. Rejected alternatives:
> `Filter.EventuallyEq atTop` (equivalent via `Nat.cofinite_eq_atTop`, but drags in filter
> API for no gain) and `AddMonoidAlgebra`/`DFinsupp` models (wrong shape — we need the
> *product*, not the sum, as ambient). **Consequences later stages must respect:** the
> tail value `x` is **unique** (two cofinite sets meet), so Stage E should prove
> `tailValue : Ramp → Balg` well-defined as a support lemma; `uAt n` has support exactly
> `{n}` and `uAt n ≠ 0` reduces to `uElt ≠ 0`; and `diag` is a ring hom split by
> `tailValue`, i.e. `tailValue (diag x) = x`.

A definition once frozen is binding: later stages may *characterize* it with support lemmas
but may never redefine or silently swap it.

> **Cheat watch (Defs).** Every predicate must be the **genuine textbook notion**, quantified
> exactly as `SKETCH.md` states it. Concretely, for this problem:
> * `QuasiCoherent` must quantify over **all** `n : ℕ` and **all** `f : Fin n → S`. Replacing
>   it by "`n = 3`", by "for the specific family `![a,b,a+b]`", or by "for all `n ≤ 2`" is a
>   cheat — the first two make `R_not_quasiCoherent` trivial-by-construction, the third makes
>   it **false** (our `R` *is* finite conductor).
> * `FiniteConductor` must have **no extra hypothesis** — not "for `x` a nonzerodivisor",
>   not "for `x ∈ m`", not "for `x ≠ 0`". `R_finiteConductor` is the hard half; weakening
>   its definition is the easiest way to fake the whole project.
> * `ann` must be `(0 : x)` and not `(0 : x)ᵣₐ𝑑` or `Ideal.span {x}`'s annihilator-of-something-else.
> * `relIdeal` must use `mPol ^ 3` and `X 0 * X 3 + X 1 * X 2`. `mPol ^ 2` would make `B`
>   have `m² = 0`, killing `u`; dropping `ad + bc` would make `aB ⊓ bB ⊓ (a+b)B ≠ ⊥`.
> * `Ideal.FG` must be Mathlib's `Submodule.FG` (∃ a finite generating set). Do not
>   substitute "generated by ≤ k elements for some k I can compute" or a cardinality bound.

### 5. The iteration loop & agent-onboarding protocol

After SETUP, the project is driven by an **orchestrator** that runs repeated iterations.
Each iteration has three phases, executed by short-lived agents that share **no memory**
beyond the files on disk — they coordinate entirely through `TASKS.md`, `PROGRESS.md`, and
`REVIEW.md` (all append-only):

1. **PLAN** — one agent reads `REVIEW.md` (the auditor's prior findings — its "Required
   follow-ups" are top priority), `PROGRESS.md` (what is `✅`/`🔧`/`⚠️`/`📝`), `SKETCH.md`,
   and `BLUEPRINT.md`. It chooses the most valuable batch of work that respects the
   dependency graph, splits it across **up to 4 parallel workers with NON-OVERLAPPING
   files**, and **appends a `## Iteration N` block to `TASKS.md`** with one `Agent k:` line
   per active worker (inactive workers omitted). It writes no proofs.
2. **WORKERS** — up to 4 agents run **in parallel**, one per `Agent k:` line. Each owns only
   the files its line assigns (this is what makes parallelism collision-free).
3. **REVIEW** — one independent, adversarial auditor re-runs the build, `#print axioms`, and
   `scripts/verify.py`, checks faithfulness against `SKETCH.md`/`BLUEPRINT.md`, and
   **appends a `## Review — Iteration N` block to `REVIEW.md`** ending in
   `Verdict: COMPLETE | INCOMPLETE`. Every 5th iteration is a full-project audit. The loop
   ends when a verdict is `COMPLETE` and a final full audit confirms it.

**Worker onboarding ritual — do this BEFORE writing any code:**

1. **Read `TASKS.md`**, find `## Iteration N`, then your own `Agent k:` line. *That line is
   your assignment* — the files you own and the lemmas to produce. Ignore the other agents'
   lines (they are running right now in parallel).
2. **Read `PROGRESS.md` end to end.** Respect every `✅` (done — reuse, don't redo), `🔧`
   (another agent holds it — do not touch), `⚠️` (blocked), and `📝` (a fixed modeling/proof
   decision you must follow).
3. **Read the `BLUEPRINT.md` stage(s) your task names — including the Cheat-watch box — and
   the cited `SKETCH.md` step(s).** Do not work from the stage title alone; the cheat-watch
   boxes are binding.
4. **Append a `🔧 in progress` entry** to `PROGRESS.md` claiming your work, then work only on
   your assigned files, then append `✅`/`⚠️` as you go.

**Dependency discipline.** Respect the order graph in "Suggested formalization order"; the
Plan agent must never assign work whose prerequisites are not yet `✅`. Workers must **never
edit the frozen `Defs.lean`/`Theorems.lean`** and must **never weaken a frozen statement**
(see the cardinal cheat rule below) — if a task seems to need that, append a `⚠️` entry
describing the obstacle and stop, rather than touching a frozen file.

### Stage A — the algebra `B`: normal form, Noetherianity, `m³ = 0` (`Proofs/StageA_Algebra/`)

Goal: make `Balg` *computable-about*. Delivers frozen theorems `B_nontrivial`, `B_relation`,
`B_isNoetherianRing`, `B_maximalIdeal_pow_three`, and — most importantly — the support
infrastructure every later stage leans on: a `ZMod 2`-linear **normal form** for `Balg`.

**A1 — `B_relation`.** `xa * xd + xb * xc = 0`. Immediate:
`Ideal.Quotient.eq_zero_iff_mem` and `Ideal.subset_span`/`le_sup_right`. Also record
`xa * xd = xb * xc` (char 2) as `B_relation'` — later stages use the equation form constantly.

**A2 — `B_maximalIdeal_pow_three`.** `mB ^ 3 = ⊥`. Route: `mB = Ideal.map (Ideal.Quotient.mk relIdeal) mPol`
(prove as `mB_eq_map`), then `mB ^ 3 = Ideal.map _ (mPol ^ 3) ≤ Ideal.map _ relIdeal = ⊥`
using `Ideal.map_pow` and `Ideal.map_eq_bot_iff_le_ker`. Corollary to record:
`mul_mem_mB_three : x ∈ mB → y ∈ mB → z ∈ mB → x * y * z = 0`.

**A3 — the normal form `nf` (the workhorse).** Let `Idx` be a `Fintype` with 14 elements —
concretely `Idx := Unit ⊕ Fin 4 ⊕ Fin 9` — indexing the monomial basis
`1; a,b,c,d; a², ab, ac, ad, b², bd, c², cd, d²` (note `bc` is **not** in the list: the
relation makes `bc = ad`). Construct
```
nfPol : Pol →ₗ[ZMod 2] (Idx → ZMod 2)
```
by `MvPolynomial.basisMonomials`-style `Finsupp` linear extension: a monomial of total
degree ≥ 3 goes to `0`; a monomial of degree ≤ 2 goes to its own basis vector, except `bc`
which goes to the basis vector of `ad`. Then prove `nfPol` kills `relIdeal`
(`relIdeal ≤ LinearMap.ker nfPol`): elements of `relIdeal` are `p·μ` with `μ` a degree-3
monomial (all monomials of the product have degree ≥ 3) plus `q·(ad+bc)` (split `q` into its
constant term — which gives `ad + bc ↦ e_ad + e_ad = 0` — and its positive-degree part,
which gives only degree ≥ 3 monomials). Descend to
```
nf : Balg →ₗ[ZMod 2] (Idx → ZMod 2)
```
and build the section `sec : (Idx → ZMod 2) →ₗ[ZMod 2] Balg` sending each index to the
corresponding monomial's class. Prove `nf ∘ sec = id` (a 14-case `decide`/`fin_cases` on
`Idx`, all inside the computable type `Idx → ZMod 2`) and `sec ∘ nf = id` (surjectivity of
`sec`: the classes of the 14 monomials span `Balg` because every monomial of degree ≥ 3 is
`0` and `bc = ad`). Package as `basisB : Basis Idx (ZMod 2) Balg` and record the evaluation
simp lemmas `nf_xa`, `nf_xb`, …, `nf_mul_xa_xb`, … .

> This is **the hardest engineering in the project**. Budget accordingly. Everything in
> Stages B and C that says "≠ 0" or "= ⊥" is discharged by applying `nf` and computing in
> `Idx → ZMod 2`, which *is* `DecidableEq` and *does* reduce.

**A4 — `B_nontrivial`.** From `basisB` (a basis of a nonzero-dimension space) or directly
from `nf 1 ≠ 0`. Do **not** prove it by `decide` on `Balg` — `Balg` is not computable.

**A5 — `B_isNoetherianRing`.** `MvPolynomial.isNoetherianRing` gives `IsNoetherianRing Pol`
(`Fin 4` is a `Fintype`, `ZMod 2` is a field hence Noetherian); then
`isNoetherianRing_of_surjective Pol Balg (Ideal.Quotient.mk relIdeal) Ideal.Quotient.mk_surjective`.
*Alternative if that transfer lemma's name has drifted:* `Balg` is a finite type (via
`basisB` and `Fintype (Idx → ZMod 2)`), and every ideal of a finite ring is `FG` because it
is generated by its own (finite) underlying set — record whichever route works as a `📝`.

**A6 — degree bookkeeping (support).** `mB = ⊤`? No — record instead:
`mem_mB_iff : x ∈ mB ↔ nf x (Sum.inl ()) = 0` ("`x` has zero constant term"), and

constant term is `1` then `x = 1 + y` with `y ∈ mB`, and `(1+y)(1+y+y²) = 1` since `y³ = 0`).

### Stage B — the colon lemma (**MILESTONE**) (`Proofs/StageB_Colon/`)

Goal: frozen theorems `B_colon_two_gen` and `B_triple_inter_eq_bot`. This stage is the
mathematical heart; nothing downstream works without B1.

**B1 — `B_colon_two_gen`.** `∀ x y : Balg, colonI (span {x,y}) mB = span {x,y} ⊔ mB ^ 2`.

*Easy inclusion (`⊇`)*: `I ≤ (I : m)` because `I·m ⊆ I`, and `mB^2 ≤ (I : m)` because
`mB^2 · mB = mB^3 = ⊥ ≤ I` (A2). Use `Submodule.mem_colon` and `sup_le`.

*Hard inclusion (`⊆`)*, by the following reduction — **prove it in exactly this order and log
each step**:
1. **Unit case.** If `x ∉ mB` or `y ∉ mB` then that generator is a unit (A6), so
   `span {x,y} = ⊤` and both sides are `⊤`.
2. **Reduce the colon element to degree 1.** Suppose `x, y ∈ mB`. Let `t ∈ (I : m)`. If
   `t ∉ mB` then `t` is a unit, so `mB ≤ I`; but `I + mB²/mB²` is spanned by the images of
   `x, y`, so `dim ≤ 2 < 4 = dim (mB/mB²)` — contradiction (use `nf` and `basisB`:
   `mB/mB²` has the 4 basis vectors `a,b,c,d`). Hence `t ∈ mB`. Writing `t = t₁ + t₂` with
   `t₂ ∈ mB²` (via `nf`), and since `mB² ≤ RHS`, it suffices to handle `t₁` — a
   **degree-1** element.
3. **Reduce `x, y` to degree 1 too.** Write `x = x₁ + x₂`, `y = y₁ + y₂`. Because
   `mB² · mB = 0`, we have `I ∩ mB² = {α x₂ + β y₂ + w x₁ + w' y₁ : α, β ∈ F₂, w, w' ∈ mB,
   α x₁ + β y₁ = 0}` — prove this as support lemma `I_meet_mB_sq`.
4. **Core linear algebra.** Let `V = ⟨a,b,c,d⟩` (the degree-1 part, 4-dimensional) and
   `W` = the degree-2 part (9-dimensional, basis `a², ab, ac, ad, b², bd, c², cd, d²`, with
   `bc = ad`). Prove the two facts that do all the work:
   - `mul_inj_of_ne_zero`: for `0 ≠ s ∈ V`, the map `V → W, w ↦ s * w` is **injective**
     (equivalently `dim (s·V) = 4`). Proof: `s * w = 0` in `B` means `s·w ∈ ⟨ad+bc⟩` in
     `Sym²`, and `ad + bc` is an irreducible quadratic form over `F₂`, so it is not a
     product of two linear forms; make this concrete via `nf` (16 choices of `s`, 16 of `w`
     — a finite check inside `Idx → ZMod 2`).
   - `dim_inter_eq_two`: for `s, s'` linearly independent in `V`,
     `dim (s·V ∩ s'·V) = 2` (e.g. `a·V ∩ b·V = ⟨ab, ad⟩`). Again a finite check via `nf`
     (there are only `16 · 16` pairs, and `GL(V)`-symmetry is *not* available, so just
     enumerate — see the note on the `decide` budget below).
   Then: if `t₁ ∉ span_{F₂}{x₁, y₁}` we get `dim (t₁·V + x₁·V + y₁·V) ≥ dim(x₁·V + y₁·V) + 2`,
   which exceeds the room available in `I ∩ mB²` by step 3, contradicting `t₁ · mB ⊆ I`.
   Handle the degenerate sub-cases (`y₁ = 0`, `y₁ = x₁`, `x₁ = y₁ = 0`) separately; in the
   last one `I ⊆ mB²` has `F₂`-dimension ≤ 2 while `t₁ · V` has dimension 4.
5. Conclude `t₁ ∈ span {x, y} ⊔ mB ^ 2`.

*Practical note on the `decide` budget.* The finite checks in step 4 range over `V ≅ (ZMod 2)⁴`
(16 elements) and `W ≅ (ZMod 2)⁹`, all transported through `nf` into `Idx → ZMod 2`, which is
a genuinely computable type. A single `∀ s w : Fin 4 → ZMod 2` check (256 cases) is fine for
kernel `decide`; a triply-quantified check over `V³` (4096 cases) **times** a span-membership
search is **not** — factor it: prove the two sublemmas above as standalone `decide`-able
statements about explicit coordinate vectors, then do the dimension count structurally.
`native_decide` is banned; if a `decide` times out, restructure, do not switch tactic.

**B2 — `B_triple_inter_eq_bot`.** `span {xa} ⊓ span {xb} ⊓ span {xa + xb} = ⊥`.
Route (independent of B1, so it can be proved in parallel): `B` is graded, so
`s·B = F₂·s ⊕ s·V` for `s ∈ V`. Take `z` in the triple intersection.
Degree-1 parts: `⟨a⟩ ∩ ⟨b⟩ = 0` in `V`, so the degree-1 component of `z` is `0`.
Degree-2 parts: `a·V ∩ b·V = ⟨ab, ad⟩` (from `dim_inter_eq_two` / a direct `nf`
computation), and
`(a+b)·V = ⟨a² + ab, ab + b², ac + ad, ad + bd⟩`; expanding `λ·ab + μ·ad` in the latter basis
forces the coefficients of `a²`, `b²`, `ac`, `bd` to vanish, hence `λ = μ = 0`.
All of this is coordinate arithmetic in `Idx → ZMod 2` via `nf`.

> **Cheat watch (Stage B).** (a) `B_colon_two_gen` is a `∀ x y : Balg` statement over the
> **whole** ring (all `2¹⁴` elements each) — proving it only for `x, y ∈ {xa, xb, xc, xd, xa+xb}`,
> or only for `x, y ∈ mB`, or only "for the `I` we actually use", is the single most
> tempting cheat in this project and would silently make Stage C false-but-derivable. The
> unit case and the degenerate `x₁, y₁` cases are **part of the theorem**; do not skip them
> with `sorry`, `omega`-style hand-waving, or an added hypothesis.
> (b) Do not prove `⊇` and call it done: the content is `⊆`. Watch for accidentally proving
> `colonI I mB = ⊤` (true only when `I = ⊤`).
> (c) `B_triple_inter_eq_bot` must be `= ⊥`, not `≤ mB²` or "contains no unit". A one-sided
> inclusion here breaks Stage F, where we need every element of `J` to have **finite support**.
> (d) Do not weaken `span {x, y}` to `span {x}`; the two-generator case is exactly what
> `M_pair_inter` consumes.
> (e) Guardrail `example`s: `example : colonI (⊥ : Ideal Balg) mB = mB ^ 2 := by ...`
> (the `I = 0` instance — if this fails, the reduction is wrong) and
> `example : xa * xb ∈ Ideal.span {xa} ⊓ Ideal.span {xb} := by ...` (the pairwise
> intersection is **not** zero — if you "prove" it is, you have collapsed `B`).

### Stage C — the module `M` (`Proofs/StageC_Module/`)

Goal: frozen theorems `M_ann_eq`, `M_pair_inter`, `M_u_ne_zero`, `M_u_mem_triple`,
`M_triple_defect`. Depends on Stage B (C1, C2) and Stage A (C3, C4).

**C0 — presentation lemmas (support).** From `Mmod = (Fin 4 → Balg) ⧸ Nsub`:
`mem_Nsub : w ∈ Nsub ↔ ∃ t : Balg, w = t • vvec` (`Submodule.mem_span_singleton`), and
`ann_vvec : (∀ i, t * vvec i = 0) ↔ t ∈ mB ^ 2` — i.e. `(0 : v) = mB²`, which is the
`I = ⊥` instance of `B_colon_two_gen` (`colonI ⊥ mB = mB ^ 2`). Record also
`smulTop_span_singleton_mem : m ∈ smulTop (Ideal.span {x}) ↔ ∃ n : Mmod, x • n = m`.

**C1 — `M_ann_eq`.** `annM Mmod x = smulTop (ann x)`, i.e. `(0 :_M x) = (0 :_B x)·M`.
`⊇` is formal. For `⊆`: let `m̄ = ⟦p⟧` with `x • m̄ = 0`, i.e. `x • p = t • vvec` for some
`t`. Then for every `i`, `t * vvec i = x * p i ∈ span {x}`, so
`t ∈ colonI (span {x, x}) mB = span {x} ⊔ mB ^ 2` by **B1**. Write `t = x*s + z`, `z ∈ mB²`,
so `z • vvec = 0` by C0, hence `x • (p - s • vvec) = 0` coordinatewise, i.e.
`p - s • vvec ∈ (ann x) • (Fin 4 → Balg)`; its class is `m̄`, so `m̄ ∈ smulTop (ann x)`. ∎

**C2 — `M_pair_inter`.** `xM ⊓ yM = (xB ⊓ yB)M`. `⊇` is formal (`Submodule.smul_mono`).
For `⊆`: let `m̄ = x • ⟦p⟧ = y • ⟦q⟧`, so `x • p - y • q = t • vvec`. Coordinatewise
`t * vvec i ∈ span {x, y}`, so by **B1** `t = x*α + y*β + z` with `z ∈ mB²`, and
`z • vvec = 0`. Put `p' := p - α • vvec`, `q' := q + β • vvec`; then `⟦p'⟧ = ⟦p⟧`,
`⟦q'⟧ = ⟦q⟧`, and **`x • p' = y • q'` exactly in `B⁴`**. Hence each coordinate
`x * p' i = y * q' i ∈ span {x} ⊓ span {y}`, so
`x • p' ∈ (span {x} ⊓ span {y}) • (Fin 4 → Balg)` and its class `m̄` lies in
`smulTop (span {x} ⊓ span {y})`. ∎
*(This is the `Tor₁ = 0` argument of `SKETCH.md` Step 2, spelled out without `Tor`.)*

**C3 — `M_u_mem_triple`.** Use the three explicit witnesses recorded in D3 — each is a
one-line `Submodule.Quotient.mk` computation in `B⁴`, needing only `B_relation'`
(`xa*xd = xb*xc`) and `ring`/`decide`-free `simp`:
- `uElt = xb • ⟦![0, xa + xb, 0, xc + xd]⟧` — exact in `B⁴`, no `v`-correction.
- `uElt = (xa + xb) • ⟦![0, xb, 0, xd]⟧` — exact in `B⁴`, uses `xa*xd = xb*xc`.
- `uElt = xa • ⟦![xb, xb, xd, xd]⟧` — here the `B⁴`-level identity is
  `![0, ab+b², 0, bc+bd] = xa • ![xb,xb,xd,xd] + xb • vvec`, so the equality holds **in the
  quotient**; check all four coordinates, using `xa*xd + xb*xc = 0` in coordinate 3 and
  `xa*xd = xb*xc` in coordinate 4.

**C4 — `M_u_ne_zero`.** `uElt ≠ 0` means `![0, ab+b², 0, bc+bd] ∉ Nsub`, i.e. there is no
`t : Balg` with `t • vvec = ![0, xa*xb + xb*xb, 0, xb*xc + xb*xd]`. Proof via `nf`:
coordinate 2 forces (after killing the constant term of `t`, which would make coordinate 2
degree-1) the degree-1 part of `t` to be exactly `xa + xb` — because in `W` the vectors
`ab, b², ad(=bc), bd` are part of the basis, so `t₁ = λ₁a+λ₂b+λ₃c+λ₄d` with
`t₁·b = λ₁ab + λ₂b² + λ₃ad + λ₄bd = ab + b²` forces `λ = (1,1,0,0)`. But then coordinate 1
gives `t * xa = (xa+xb)*xa = a² + ab ≠ 0`, contradicting the required `0`. Each step is an
`nf` coordinate computation. ∎

**C5 — `M_triple_defect`.** Combine: by `B_triple_inter_eq_bot` the RHS is
`smulTop ⊥ = ⊥`, while by C3 + C4 the LHS contains `uElt ≠ 0`. Two lines.

> **Cheat watch (Stage C).** (a) `M_ann_eq` and `M_pair_inter` are `∀ x` / `∀ x y` over the
> **whole** of `Balg`. Do not prove them only for `x, y ∈ {xa, xb, xa+xb}` — Stage D
> instantiates them at arbitrary elements and the weakening would be invisible there.
> (b) Both are **equalities**. The formal inclusion (`⊇`, resp. `≤`) is free; a proof that
> only establishes it is worth nothing. Check which direction your proof actually does.
> (c) `M_u_ne_zero` must be a genuine non-membership *computed* via `nf`, never
> `by decide` (`Mmod` is not computable), never `by simp` on faith, and never obtained by
> assuming `Nsub ≠ ⊤`.
> (d) Do not "simplify" `uElt` to a different element that is easier to handle: it is frozen.
> (e) Do not conflate `Nsub : Submodule Balg (Fin 4 → Balg)` with an ideal of `Balg`, and do
> not conflate `smulTop (Ideal.span {x}) : Submodule Balg Mmod` with
> `Ideal.span {x} : Ideal Balg`. Mixing the module side and the ring side is the most likely
> *silent* bug in this stage.
> (f) Guardrail `example`: `example : (smulTop (Ideal.span {xa}) : Submodule Balg Mmod) ≠ ⊥`
> — if `aM` is zero you have collapsed `M`.

### Stage D — the idealization `C = B ⋉ M` (`Proofs/StageD_Idealization/`)

Goal: frozen theorems `C_isNoetherianRing`, `C_ann_eq`, `C_pair_inter`, `C_triple_defect`.
Depends on Stage C.

**D1 — `map_iota_eq` (support, prove first).** For any ideal `J : Ideal Balg`,
`Ideal.map iota J = {c : Cring | c.fst ∈ J ∧ c.snd ∈ smulTop J}`. `≤` by
`Ideal.map_le_iff_le_comap` + generators; `≥` by writing
`c = TrivSqZeroExt.inl c.fst + TrivSqZeroExt.inr c.snd` and expanding `c.snd` as a finite
sum `Σ jₖ • nₖ` with `jₖ ∈ J`, each term being `iota jₖ * TrivSqZeroExt.inr nₖ`.
Corollary `iota_mem_map_iff : iota z ∈ Ideal.map iota J ↔ z ∈ J` — used in Stage E.

**D2 — `span_iota_eq` (support).** `Ideal.span {iota x} = {c | c.fst ∈ span {x} ∧ c.snd ∈ smulTop (span {x})}`,
because `iota x * (z, n) = (x*z, x • n)` and both components range freely. This is the
`J = span {x}` case of D1 but is worth its own name.

**D3 — `C_ann_eq`.** `ann (iota x) = (ann x).map iota`. Using
`iota x * (z, n) = (x*z, x • n)`, an element `(z,n)` annihilates `iota x` iff `z ∈ ann x`
and `n ∈ annM Mmod x`; by **`M_ann_eq`** the latter is `smulTop (ann x)`; by **D1** that is
exactly membership in `(ann x).map iota`. ∎

**D4 — `C_pair_inter`.** `span {iota x} ⊓ span {iota y} = (span {x} ⊓ span {y}).map iota`.
By D2 the LHS is `{c | c.fst ∈ xB ⊓ yB ∧ c.snd ∈ xM ⊓ yM}`; by **`M_pair_inter`** the second
condition is `c.snd ∈ smulTop (xB ⊓ yB)`; by D1 that is the RHS. ∎

**D5 — `C_isNoetherianRing`.** Route: `Cring` is a finitely generated `Balg`-module
(`Cring ≃ₗ Balg × Mmod` as `Balg`-modules; `Mmod` is a quotient of `Balg⁴`, hence f.g.), and
`Balg` is Noetherian (**`B_isNoetherianRing`**), so `Cring` is a Noetherian `Balg`-module
(`isNoetherian_of_fg_of_noetherian'` / `Module.Finite` + `IsNoetherian`). Every ideal of
`Cring` is in particular a `Balg`-submodule (restriction of scalars along
`iota`/`algebraMap`), hence f.g. **as a `Balg`-module**, hence a fortiori f.g. as a
`Cring`-ideal (the same finite set generates a larger ideal, and it is contained in the
original — spell this out as `fg_of_fg_restrictScalars`). Then `isNoetherianRing_iff` /
`Ideal.fg_iff`. *Alternative fallback:* `Cring` is a **finite type** (`Balg` and `Mmod` are
both finite via `basisB`), and every ideal of a finite ring is f.g. by taking the ideal
itself as generating set. Log whichever route succeeds as `📝`.

**D6 — `C_triple_defect`.** By `B_triple_inter_eq_bot` the RHS is `(⊥).map iota = ⊥`. For the
LHS: `TrivSqZeroExt.inr uElt` lies in each of `span {iota xa}`, `span {iota xb}`,
`span {iota (xa+xb)}` by D2 + **`M_u_mem_triple`** (its `fst` is `0 ∈ span {x}` and its `snd`
is `uElt ∈ xM`), and it is nonzero by **`M_u_ne_zero`** (`TrivSqZeroExt.inr` is injective). ∎

> **Cheat watch (Stage D).** (a) `C_ann_eq` and `C_pair_inter` are `∀ x` / `∀ x y` over all
> of `Balg` — they are *not* statements about `xa, xb` only, and Stage E instantiates them at
> arbitrary tail values.
> (b) The right-hand sides are **extensions of ideals of `B`** (`Ideal.map iota`), not
> "ideals of `C` that happen to contain the image". Do not replace `Ideal.map iota J` by
> `Ideal.comap`-flavoured surrogates or by `Ideal.span (iota '' J)` without proving they
> agree (they do — `Ideal.map` is defined as the latter — but say so once and stick to one).
> (c) Do **not** prove `C_isNoetherianRing` by declaring `Cring` Noetherian as an
> *instance* obtained from a `sorry`ed helper, and do not weaken it to "`Cring` is
> Noetherian as a `Balg`-module" — Stage E needs f.g. of `Cring`-**ideals**.
> (d) Do not conflate `iota x` with `x`, or `TrivSqZeroExt.inr uElt` with `uElt`.
> (e) Guardrail `example`: `example : (TrivSqZeroExt.inr uElt : Cring) ≠ 0 := by ...` and
> `example : (1 : Cring) ≠ 0 := by ...`.

### Stage E — `R = Δ(B) + C^(ℕ)` is finite conductor (`Proofs/StageE_Amplify/`)

Goal: the frozen theorem `R_finiteConductor`. This is the **hardest bookkeeping** in the
project (Stage B is the hardest mathematics). Depends on Stage D.

**E0 — `Ramp` infrastructure (support).**
- `tailValue : Ramp → Balg` together with `tailValue_spec : {n | (f : ℕ → Cring) n ≠ iota (tailValue f)}.Finite`
  and uniqueness (`tail_unique`: two cofinite sets meet, so the witness `x` is unique —
  needs `Set.Infinite` of the complement of a finite set in `ℕ`, i.e. `Set.Infinite.mono` +
  `Set.infinite_of_not_bddAbove` or simply `Set.Finite.union` + `Set.infinite_univ`).
  Define via `Classical.choose` and prove `tailValue` is a ring hom (`tailValue_add`,
  `tailValue_mul`, `tailValue_one`) — used only for readability, not essential.
- `exc : Ramp → Set ℕ`, the exceptional set `{n | f n ≠ iota (tailValue f)}`, with
  `exc_finite`.
- `coordAt (n : ℕ) (c : Cring) : Ramp` — the element that is `c` at `n` and `0` elsewhere
  (in `Rsub` with tail value `0`). Simp lemmas: `coordAt_apply_self`, `coordAt_apply_ne`,
  `coordAt_mul` (`coordAt n c * f = coordAt n (c * f n)`).
- `offSet (S : Set ℕ) (hS : S.Finite) (x : Balg) : Ramp` — the element equal to `iota x` off
  `S` and `0` on `S`. Simp lemmas as above.
- `mem_ideal_span_finite`: an element of `Ideal.span (↑s)` for `s : Finset Ramp` is a finite
  `R`-combination (`Submodule.mem_span_finset`).

**E1 — `R_ann_fg` (first half of `FiniteConductor`).** Let `f : Ramp`, `x := tailValue f`,
`S := exc f` (finite). Take:
- `w₁, …, w_k` a finite generating set of `ann x : Ideal Balg` (exists: **`B_isNoetherianRing`**);
- for each `n ∈ S`, a finite generating set `c_{n,1}, …` of `ann (f n) : Ideal Cring`
  (exists: **`C_isNoetherianRing`**).
Claim: `ann f = Ideal.span ({offSet S _ w_j} ∪ {coordAt n c_{n,i}})`, a finite set.
`⊇`: each listed element kills `f` coordinatewise (off `S`, `iota x * iota w_j = iota (x*w_j) = 0`;
on `S`, `f n * c_{n,i} = 0`).
`⊆`: given `g` with `f * g = 0`, let `z := tailValue g`; off `S ∪ exc g` we get
`iota x * iota z = 0`, so `x * z = 0` (`iota` injective), i.e. `z ∈ ann x`; write
`z = Σ β_j w_j`. Then `g' := g - Σ diag(β_j) * offSet S _ w_j` has **finite support**
(contained in `S ∪ exc g`), and for each `n` in that support `g' n ∈ ann (f n)` — off `S`
this uses **`C_ann_eq`** to know `g' n ∈ (ann x).map iota` and then rewrites it through the
`offSet` generators; on `S` it is the definition of `c_{n,i}`. Finally
`g' = Σ_{n ∈ supp} coordAt n (g' n)`, a finite sum of elements of the span. ∎

**E2 — `R_pair_inter_fg` (second half).** Let `f, g : Ramp`, `x := tailValue f`,
`y := tailValue g`, `S := exc f ∪ exc g` (finite). Take:
- `w₁, …, w_k` a finite generating set of `span {x} ⊓ span {y} : Ideal Balg`
  (**`B_isNoetherianRing`**);
- for each `n ∈ S`, a finite generating set of `span {f n} ⊓ span {g n} : Ideal Cring`
  (**`C_isNoetherianRing`**).
Claim: `Ideal.span {f} ⊓ Ideal.span {g}` is generated by
`{offSet S _ w_j} ∪ {coordAt n c_{n,i}}`.
`⊇`: `offSet S _ w_j ∈ f·R` because `w_j = x * x'` for some `x'` and
`f * offSet S _ (x') = offSet S _ w_j` (off `S`, `f n = iota x`; on `S` both sides are `0`);
symmetrically for `g`. And `coordAt n c ∈ f·R` because `c ∈ (f n)·Cring`.
`⊆`: given `h = f * s = g * t`, let `z := tailValue h`. Off `S ∪ exc h` we have
`h n ∈ span {iota x} ⊓ span {iota y} = (span {x} ⊓ span {y}).map iota` by **`C_pair_inter`**,
and `h n = iota z`, so `z ∈ span {x} ⊓ span {y}` by `iota_mem_map_iff` (D1). Write
`z = Σ β_j w_j`, subtract `Σ diag(β_j) * offSet S _ w_j`; the remainder `h'` has finite
support, and at each `n` in that support `h' n` lies in `span {f n} ⊓ span {g n}` — off `S`
it is in `(span{x} ⊓ span{y}).map iota`, hence an `iota`-combination of the `w_j`, hence in
the span of the `offSet` generators after multiplying by `coordAt n`; on `S` it is covered by
the `c_{n,i}`. Sum up. ∎

**E3 — `R_finiteConductor`.** `⟨E1, E2⟩`.

> **Cheat watch (Stage E).** (a) `FiniteConductor Ramp` is `∀ f` and `∀ f g` over the **whole
> ring** `Ramp` — do not prove it only for `f, g` in the image of `diag`, only for finitely
> supported `f`, or only for `f` with `tailValue f ≠ 0`. The whole point of Step 5 is that
> the *mixed* case (finite exceptional set + constant tail) works.
> (b) Do not silently use "`R` is Noetherian" — it is **not** (that is exactly what Stage F
> refutes). Every finiteness must come from `B` or `C` being Noetherian plus the finite
> exceptional set.
> (c) Do not replace `Ideal.FG` by "generated by the `w_j`" without proving the reverse
> inclusion — the `⊆` direction is the content; `⊇` is easy.
> (d) The tail argument **needs `C_pair_inter` at arbitrary `x, y`**, not at `xa, xb`. If you
> find yourself wanting `x, y ∈ {xa, xb}`, you have mis-structured the proof.
> (e) Do not assume the exceptional sets of `s` and `t` are contained in `S`; only `f` and
> `g` control `S`. Handle `exc h` separately (it is finite, that is all you need).
> (f) Guardrail `example`: `example : (diag xa : Ramp) ≠ 0 := by ...` and
> `example : uAt 0 ≠ (0 : Ramp) := by ...` — if either fails, `Rsub` is mis-modelled.

### Stage F — the triple intersection in `R`, and the headline (`Proofs/StageF_Headline/`)

Goal: frozen theorems `R_triple_inter_not_fg`, `R_not_quasiCoherent`,
`quasiCoherent_imp_finiteConductor`, `exists_finiteConductor_not_quasiCoherent`.
Depends on Stages B, C, D, E. (`quasiCoherent_imp_finiteConductor` depends on nothing and
can be proved on day one — assign it early to fill a parallel slot.)

**F1 — `uAt_mem_triple` (support).** For every `n`,
`uAt n ∈ Ideal.span {diag xa} ⊓ Ideal.span {diag xb} ⊓ Ideal.span {diag (xa + xb)}`.
Because `TrivSqZeroExt.inr uElt ∈ span {iota xa}` etc. (Stage D, D6), pick for each of the
three the `Cring` witness `c` with `iota s * c = TrivSqZeroExt.inr uElt`, and then
`diag s * coordAt n c = uAt n` (check coordinatewise: at `n` it is `iota s * c`; elsewhere `0`).

**F2 — `uAt_ne_zero` (support).** `uAt n ≠ 0`, from `M_u_ne_zero` and injectivity of
`TrivSqZeroExt.inr`, plus `Subtype.ext_iff` / `funext` at coordinate `n`.

**F3 — `support_of_mem_triple` (support).** Every `h` in
`J := span {diag xa} ⊓ span {diag xb} ⊓ span {diag (xa+xb)}` has **finite support**, i.e.
`tailValue h = 0`. Proof: off `exc h`, `h n = iota (tailValue h)` and (by D2 + the
`fst`-projection) `tailValue h ∈ span {xa} ⊓ span {xb} ⊓ span {xa + xb} = ⊥` by
**`B_triple_inter_eq_bot`**. (Use that the exceptional set's complement is nonempty because
`ℕ` is infinite.) So `tailValue h = 0` and `supp h := exc h` is finite.

**F4 — `R_triple_inter_not_fg`.** Suppose `J = Ideal.span ↑s` with `s : Finset Ramp` finite.
Let `T := ⋃ h ∈ s, exc h` — finite by F3 + `Set.Finite.biUnion`. Every element of
`Ideal.span ↑s` is a finite combination `Σ r_h * h` (`Submodule.mem_span_finset`), and
`(r_h * h) n = r_h n * h n = 0` for `n ∉ exc h`; hence every element of `J` vanishes outside
`T`. Choose `n ∉ T` (possible: `T` finite, `ℕ` infinite). By F1, `uAt n ∈ J`, so
`uAt n` vanishes at `n` — but `(uAt n) n = TrivSqZeroExt.inr uElt ≠ 0` by F2. Contradiction. ∎

**F5 — `R_not_quasiCoherent`.** Instantiate the second clause of `QuasiCoherent Ramp` at
`n := 3` and `f := ![diag xa, diag xb, diag (xa + xb)]`, rewrite
`⨅ i : Fin 3, span {f i}` into the binary meets (`iInf` over `Fin 3`: `Fin.cases`/`decide`
on the index, or `iInf_eq_iInf_finset` + `Finset.inf`), and apply **F4**. ∎

**F6 — `quasiCoherent_imp_finiteConductor`.** Given `⟨h₁, h₂⟩ : QuasiCoherent S`, produce
`⟨h₁, fun x y => ?_⟩`: apply `h₂ 2 ![x, y]` and rewrite `⨅ i : Fin 2, span {![x,y] i}` as
`span {x} ⊓ span {y}`. Two lines; no dependencies. ∎

**F7 — `exists_finiteConductor_not_quasiCoherent` (HEADLINE).**
`⟨Ramp, inferInstance, R_finiteConductor, R_not_quasiCoherent⟩`. Require a clean
`#print axioms` here and at every stage above.

> **Cheat watch (Stage F).** (a) `R_not_quasiCoherent` must **negate the frozen
> `QuasiCoherent`** — the one quantified over all `n` and all `f`. Do not restate it as
> "the specific triple is not f.g." and call that `¬ QuasiCoherent`; `R_triple_inter_not_fg`
> is frozen separately precisely so both appear.
> (b) In F4, "every finitely generated ideal is supported on finitely many coordinates" must
> be *proved* from `Submodule.mem_span_finset`, not asserted. In particular do not assume
> the generators are the `uAt n` themselves.
> (c) F3 must use `B_triple_inter_eq_bot` (`= ⊥`); an inclusion `≤ mB²` would leave a
> nonzero tail and the argument collapses.

## Notes, risks, and cheats to watch out for

These are **general anti-cheat principles** — keep them, and the problem-specific traps are
appended at the end.

- **★ NEVER assume something as a hypothesis (the cardinal rule).** Every frozen theorem must
  be hypothesis-free wherever the source claim is unconditional. Forbidden moves: adding
  `(h : …)` to a frozen statement; proving a `∀ x` (or `∀ x y`) claim only for generators / a
  finite subset and claiming the general case; replacing an equality with a one-sided
  inclusion. If a sub-proof seems to need an assumption, **derive it or restructure** — do
  not weaken the statement. (Downstream stages typically instantiate these at *arbitrary*
  elements, so a quiet weakening breaks the assembly silently.)

- **Keep every predicate the textbook definition — do not soften it.** Quantifiers must match
  the source exactly (e.g. "for all finite families" must not become "for `n ≤ 2`" or "for
  one fixed family"); genuine finite generation must not be replaced by a cardinality-bounded
  or "I-couldn't-find-it" surrogate. A softened predicate can make the headline vacuous.

- **Get the modeling right once, in SETUP, and freeze it.** A dropped or extra relation in a
  frozen definition silently changes the object and can break the proof downstream. Validate
  the core modeling facts *before* freezing, with small guardrail `example`s that confirm the
  structure is the intended one (and that "live" relations do not secretly collapse distinct
  nonzero elements to zero).

- **Discharge ring/structure axioms once — never `sorry` them.** Inherit them from Mathlib
  (`Ideal.Quotient`, `TrivSqZeroExt`, `Subring`, `Pi`) or discharge them by `decide` on a
  finite model. If you feel the urge to `sorry` associativity or commutativity, you modeled
  the object wrong.

- **Keep module-side and ring-side objects distinct.** `Nsub` is a submodule of `Balg⁴`;
  `mB`, `ann x`, `span {x}` are ideals of `Balg`; `smulTop I` is a submodule of `Mmod`;
  `Ideal.map iota J` is an ideal of `Cring`. Fix the precise Lean form of each and do not
  conflate them — this is the most likely *silent* modeling bug in this project.

- **`decide` budget — and `native_decide` is BANNED.** `Balg`, `Mmod`, `Cring`, `Ramp` are
  **not** computable types (`Ideal.Quotient` / `Submodule.Quotient` / `Classical.choose`), so
  `decide` will not reduce on them at all. Every finite check must be transported through
  `nf` into `Idx → ZMod 2` (or `Fin 4 → ZMod 2`), which *is* computable. Even there, budget:
  256 cases is fine, 4096 cases times a span-membership search is not — factor the check.
  `native_decide` adds a compiler-trust axiom and would dirty `#print axioms` — never use it.

- **Don't touch the frozen files after SETUP.** `Defs.lean` and `Theorems.lean` are byte-frozen
  during proving (pinned in `scripts/frozen.sha256`). If a *definition* seems missing, it
  belongs in a `Proofs/` support file. If a *statement* seems wrong, stop and re-read
  `SKETCH.md` — the frozen statements are deliberately the minimal faithful rendering of the
  sketch, so a mismatch means a modeling bug to fix *before* re-freezing, not a hypothesis to
  bolt on.

- **Keep `#print axioms` clean.** Every solved theorem must depend only on
  `{propext, Classical.choice, Quot.sound}` — no `sorryAx`, no `native_decide`/`ofReduceBool`.
  `USER_NOTES.md` for this run permits **no** assumed certificates, so
  `scripts/ALLOWED_AXIOMS.txt` is empty and **no `axiom` declaration may appear anywhere**.

- **Assumed certificates go in as `axiom`s, never as hypotheses.** (Not applicable here —
  none are permitted — but the rule stands: a certificate would have to be an `axiom`
  declared in `Defs.lean` during SETUP, never a hypothesis `(h : …)` on a frozen theorem.)

**Problem-specific traps.**

- **Collapse of `B` is the top risk.** `B` is defined by relations; get one wrong and the
  ring degenerates in a way that makes *every* downstream statement provable and meaningless.
  Specifically: `mPol ^ 3` (not `^ 2`, not `^ 4`); the relation is `ad + bc` (`X 0 * X 3 +
  X 1 * X 2`), not `ab + cd`; `ZMod 2` (not `ZMod 4`, not `ℚ`). The guardrails
  `B_nontrivial`, `B_relation`, `B_maximalIdeal_pow_three` plus the `example`s in Stage A
  exist to catch exactly this — do not skip them, and do not "fix" a failing guardrail by
  changing the guardrail.

- **The `u ≠ 0` / `u ∈ triple` pair is the whole counterexample.** If `u` were `0`, `M_u_mem_triple`
  would be trivially true and the project would prove nothing. `M_u_ne_zero` must be a real
  computation through `nf`; treat any proof of it that does not mention `nf`/`basisB` as
  suspect.

- **`aB ∩ bB ∩ (a+b)B = 0` is what makes the amplification work.** It is *not* obvious and it
  is *not* "clear by degree reasons" — the degree-2 part needs the explicit basis. If this
  came out `≠ ⊥`, Stage F's "every element of `J` has finite support" would be false. Do not
  downgrade it to `≤ mB ^ 2`.

- **`R` is finite conductor but NOT Noetherian, and NOT coherent.** It is very easy to reach
  for "`R` is Noetherian" or "`R` is a subring of a Noetherian ring hence …" while doing
  Stage E. Both are false. All finiteness in Stage E must be traced back to
  `B_isNoetherianRing`/`C_isNoetherianRing` **plus** the finiteness of the exceptional set.

- **Confusing `Δ(B) + C^(ℕ)` with `C^(ℕ)` or with `C^ℕ`.** `C^ℕ` (the full product) is not
  finite conductor by this argument, and `C^(ℕ)` (the direct sum) has no identity. The tail
  value `x ∈ B` — not in `C` — is essential: it is what lets `C_pair_inter` apply at the tail.
  Check `Rsub`'s carrier reads `∃ x : Balg, {n | f n ≠ iota x}.Finite`, with `iota x`, not
  `∃ c : Cring, …`.

- **The `Tor` temptation.** `SKETCH.md` Step 2 phrases the key input homologically. Formalizing
  `Tor₁` and its long exact sequence in Mathlib is a project in itself and is **not needed**:
  Stage C gives the direct argument. An agent that starts building `Tor` machinery should be
  redirected by a `📝` entry pointing at C1/C2.
